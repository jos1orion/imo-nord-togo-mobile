# Audit technique — Immo Nord Togo

Date : 17 septembre 2026. Périmètre : APK Expo/Android, mobile React Native,
back-office Next.js et scripts Supabase présents dans ce dépôt.

## Corrections appliquées

- Les annonces publiques sont limitées côté mobile à `approved`, `available` et non expirées.
- Un statut absent est traité comme `pending`, jamais comme `approved`.
- Le rôle de l'admin mobile est maintenant lu dans `profiles.role` ; l'adresse e-mail
  codée en dur a été supprimée.
- L'API web de création de compte utilise maintenant un `upsert` de profil : elle est
  compatible avec le trigger Supabase qui crée les profils USER.
- Les logs mobiles écrivent les colonnes réellement prévues par le schéma
  (`actor_name`, pas `actor_email`/`meta`).
- Une annonce créée depuis l'admin mobile conserve le propriétaire authentifié dans
  `client_id`; les coordonnées de contact sont stockées dans les champs de contact.
  Un identifiant de locataire n'est plus envoyé dans une colonne qui référence `auth.users`.
- Les données mock du back-office ne sont plus renvoyées en production lorsqu'une API
  réelle est absente.
- Les permissions Android `SYSTEM_ALERT_WINDOW`, `READ_EXTERNAL_STORAGE` et
  `WRITE_EXTERNAL_STORAGE` ont été retirées du manifeste principal.
- `supabase-production-migration.sql` ajoute le rôle `USER` par défaut, le trigger de
  création de profils, le déclassement unique des anciens AGENT marketplace, et des
  politiques RLS restrictives.

## Scripts Supabase

La base existe déjà : exécuter d'abord `docs/supabase-user-role.sql` (seul), valider,
puis `docs/supabase-production-migration.sql` après une sauvegarde.
Ne pas utiliser `supabase-bootstrap-production.sql`, réservé à un nouveau projet vide.

Promouvoir un administrateur :

```sql
update public.profiles set role = 'ADMIN' where id = '<uuid-auth>';
```

La migration tente de planifier `expire_due_listings()` via `pg_cron` (05:00 UTC).
Si l'extension n'est pas active, l'activer dans Database > Extensions puis :

```sql
select cron.schedule('expire-imo-nord-listings', '5 0 * * *', $$select public.expire_due_listings();$$);
```

Cette fonction archive les annonces expirées et retire leurs photos du bucket
`property-images`. Les annonces expirées sont déjà masquées par RLS, même avant le
passage de la tâche planifiée.

- TypeScript back-office : succès.

## Risques restants avant production

1. La migration n'a pas été exécutée sur le projet Supabase réel dans le cadre de cet
   audit. Il faut d'abord exporter/sauvegarder la base, puis l'exécuter dans SQL Editor.
2. Les modules Messages, Avis, Agents, Documents, Transactions et Logs ont été
   retirés du menu web (redirection vers le dashboard). Ils restent du code mort
   jusqu'à un branchement Supabase volontaire.
3. Les avis, signalements, profils agents, premium et commissions restent en
   stockage local ; leurs raccourcis publics ont été masqués.
4. La compression est limitée au paramètre de qualité de l'image picker. Ajouter un
   traitement image (redimensionnement et contrôle de taille) avant un lancement large.
5. Aucun APK release signé ni test sur appareil Android réel/réseau lent n'a été exécuté.
   EAS Production doit signer l'AAB; ne pas publier une release locale signée debug.
6. Le dépôt Git ne contient pas encore de premier commit. Faire un commit avant tout
   déploiement afin de figer la version auditée.

## Décision de publication

**Non prêt pour Google Play à ce stade.** Les flux public d'annonces, authentification,
publication et sécurisation RLS sont en bonne voie après la migration; les modules
mock et les tests APK réels restent les bloqueurs principaux.
